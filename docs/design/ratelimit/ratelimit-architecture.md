# Ratelimit 模块架构设计文档

## 1. 概述

Ratelimit 模块是 Pole.io 客户端中的核心组件，负责服务调用的流量控制和访问频率限制。该模块通过统一的接口提供多种限流算法，包括 QPS 限流、并发数限流和拒绝限流。

## 2. 架构设计

### 2.1 核心组件

```
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────────┐
│ RateLimitAPI    │───▶│ RatelimitFlow    │───▶│ LimiterRegistry     │
│ (对外统一接口)   │    │ (流程编排层)     │    │ (限流器注册表)      │
└─────────────────┘    └──────────────────┘    └─────────────────────┘
                                                      │
                              ┌───────────────────────┼───────────────────────┐
                              ▼                       ▼                       ▼
                     ┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
                     │UnirateLimiter   │    │ConcurrencyLimiter│    │RejectLimiter    │
                     │(QPS限流)        │    │(并发限流)        │    │(拒绝限流)       │
                     └─────────────────┘    └──────────────────┘    └─────────────────┘
```

### 2.2 组件说明

1. **RateLimitAPI**: 提供统一的对外接口，处理用户请求。
2. **RatelimitFlow**: 流程编排层，负责规则匹配、限流器选择等。
3. **LimiterRegistry**: 限流器注册表，管理不同类型的限流器实例。
4. **ServiceRateLimiter Trait**: 插件接口，定义限流器行为。
5. **UnirateLimiter**: 单位时间内QPS限流（基于令牌桶算法）。
6. **ConcurrencyLimiter**: 并发数限制（基于信号量）。
7. **RejectLimiter**: 拒绝限流（直接拒绝请求）。

## 3. 关键实现逻辑

### 3.1 流程编排
- 解析限流规则
- 根据请求匹配对应规则
- 从注册表获取或创建限流器实例
- 执行配额检查

### 3.2 限流器生命周期
- 限流器实例按需创建（懒加载）
- 使用LRU机制自动清理过期实例
- 支持动态配置更新

## 5. 实现要点

### 5.1 QPS限流器（UnirateLimiter）
- 实现令牌桶算法
- 支持动态配置更新
- 高效的并发控制（无锁设计）

### 5.2 并发限流器（ConcurrencyLimiter）
- 基于信号量的并发控制
- 支持细粒度的并发控制
- 防止资源耗尽

### 5.3 拒绝限流器（RejectLimiter）
- 简单的开关式限流
- 用于极端情况下的流量控制

## 6. 性能要求

- 高并发支持（无锁设计）
- 低延迟（毫秒级响应）
- 内存友好（合理内存复用）
- 线程安全

## 7. 扩展性设计

- 通过 Trait 接口支持插件化扩展
- 配置热更新
- 支持多种限流算法

## 8. 错误处理

- 优雅降级策略
- 异常恢复机制
